> [!TIP]
> コードと setup アシスタントは英語を基準とします。10言語の翻訳とローカルフォントを同梱しています。`npm run setup -- --languages en,pt` は英語とポルトガル語のみを有効化し、追加パッケージのインストールや他の翻訳の削除は行いません。`--languages` を省略すると現在の選択を維持し、一覧がない設定では全10言語が有効です。英語は翻訳フォールバックとして常に有効です。`--locale en` で既定言語を指定でき、有効な言語を選べます。保存設定、対応ブラウザー言語、設定した既定値の順に解決します。言語変更でページやフォームは再読み込みせず、アラビア語の RTL も保持します。

公共アクセスでは、英語 (`en`)、スペイン語 (`es`)、ポルトガル語 (`pt`)、ドイツ語 (`de`)、フランス語 (`fr`)、イタリア語 (`it`)、簡体中国語 (`zh`)、日本語 (`ja`)、ヒンディー語 (`hi`)、アラビア語 (`ar`) がサポートされています。英語がフォールバック言語です。

## 監査と範囲

アプリケーションは Astro 静的サイトジェネレーターを使用しており、React アイランドと Better Auth によるパスワードレス認証を備えています。i18n 層は存在しません。テキストはログイン、パブリックページ、サーバーメッセージにあります。React 状態、現在のコンポーネント、既存のルートを再利用し、npm パッケージを追加しません。

ログイン、オープン登録または承認登録、メール検証、OTP、MFA、復旧コード、ヘルプ、再認証通知、エラー、バリデーション、ロード、Google 戻り、拒否されたアクセス、存在しないページが翻訳されます。OTP アクセスメールは選択した言語で送信されます。パスワード、復旧、またはパスワードのリセット画面はありません。このメカニズムは追加されません。後の拡張では、管理パネルとその設定も含みます。詳細は、[言語セレクターとパネル](workspace-i18n.md) を参照してください。

## 解像度と初期ロード

`src/lib/i18n/config.ts` は、10 個の言語、ネイティブ名、方向、`tba-language` キーを中央化します。優先順位は、有効な `localStorage` 優先度、最初の互換性のある `navigator.languages` 言語、`navigator.language`、そして最後に英語です。大文字、小文字、ハイフン、地域バリアント (例: `es-AR`、`pt-BR`、`en-GB`) が正規化されます。

`Base.astro` は、ヘッダーで同期的に同じ解決策を実行します。`lang`、`dir`、タイトルをコンテンツの表示前に設定します。静的 HTML は、最初のハイドレーションに一致するために英語を使用します。`data-auth-pending` は、`AuthI18n` が `useLayoutEffect` を使用して翻訳を適用するまで、アイランドを非表示にします。したがって、他の言語のフラッシュは表示されません。ブロックされたストレージへのアクセスはキャプチャされ、ブラウザまたは訪問状態が使用されます。

コンパクトなセレクターは、言語シンボルと独自のメニューを持つボタンを使用します。アクセス可能な名前付きの翻訳と、ネイティブ名、`lang`、`dir` を持つオプションがあります。ネイティブの隠しセレクトはシリアル化を保持します。変更すると、React コンテキストが更新され、優先順位が永続化されます。リロード、ナビゲーション、API の問い合わせはありません。フォームはマウントされません。メール、コード、登録の意図、ステップ、デバイスの信頼性、再送信の待機、エラー、進行中の操作が保持されます。エラーはキーを保持するため、表示されている間も言語が変更されます。選択した言語は訪問間で永続化され、フィールドとコードはストレージに保存されません。

## カタログ、エラー、メール

`src/lib/i18n/messages/*.json` には、言語ごとに 112 個のキーがあります。`catalog.ts` はキーを型付けし、パラメーターを補間し、英語に欠けているものを解決します。未知のキーは、内部キーではなく、公開されたエラーを表示します。マーク、入力されたメール、コード、組織名はデータであり、翻訳ではありません。

`errors.ts` は、既存のパブリック メッセージと API の既知のコードをプレゼンテーション キーに変換します。未知のエラーはサーバーの詳細を公開しません。フィールドはサーバーの制約とバリデーションを保持し、ブラウザにインストールされた言語に依存するネイティブ メッセージの代わりに、ローカルに翻訳されたバリデーションを表示します。アラビア数字、ペルシア数字、デヴァナーガリー、全角の OTP は、同じ 6 つの ASCII 桁に正規化されます。復旧コードは変更されません。

`X-Auth-Language` は有効なメール言語を選び、権限には使いません。有効なヘッダーや受信者設定がなければアプリ既定値（初期は英語）を使用し、無効化された保存言語も既定値に戻します。未翻訳キーは英語へ戻ります。確認済みログイン・登録とパネル選択が既存 `verification` メタデータ（`mail-language:<userId>`）へ設定を保存し、遅延通知は受信者の言語を使います。変更でコードを再送せず、有効期限・試行回数・検証も変えません。旧エラー文も互換性のため認識します。

Turnstileは選択された言語を受け取り、`zh-CN` を中国語簡体字に設定します。言語を変更すると、ウィジェットが再作成され、インターフェイスが更新されます。これにより、前のCAPTCHAテストが無効になり、更新されたウィジェットのテストが必要になります。ただし、フォームの他のデータとサーバーの制御は保持されます。

## デザイン、RTL、フォント

アラビア語は `dir=rtl` を設定し、ナビゲーションの矢印を逆にし、画像パネル、ヘルプの終了、配置を調整します。メールとコードはLTRとバイディレクショナル分離を使用します。ヘッダーは複数行をサポートし、長いテキストは調整され、ラベルは固定幅に依存しません。既存のアイデンティティ、テーマ、モバイル対応は維持されます。

WOFF2フォントは `public/fonts` から提供され、既存の `font-src 'self'` ポリシーが使用されます。Interフォントはラテン語の言語に使用され続けます。TBA ArabicとTBA Devanagariのフォントファミリーは、Notoフォントのグリフを保持します。TBA ChineseとTBA Japaneseには、中国語、 日本語、英語のカタログとセレクタ名が含まれます。拡張にはパネルカタログも含まれます。システムフォントは他のデータ文字をカバーします。ブラウザが必要とするフォントのみがダウンロードされます。フォントプロバイダーへのリクエストはありません。

フォントはNoto Sans Arabic、Noto Sans Devanagari、Noto Sans CJKから提供され、[SIL OFL 1.1](../licenses/noto-fonts.txt)ライセンスが適用されます。変更されたフォントファミリーは名前が変更されました。CJKカタログに文字を追加した後、フォントを再生成するには、Noto、fontTools、Brotliを使用したメンテナンス環境で `/usr/bin/python3 scripts/build-auth-fonts.py /usr/share/fonts` を実行します。これはオプションのツールです。ビルドとアプリケーションにはPythonまたは新しい依存関係は必要ありません。再配布では、リポジトリ内のライセンスが保持されます。

## 実装ファイル

- 設定、解決、カタログ、エラー: `src/lib/i18n/config.ts`、`catalog.ts`、`errors.ts`、および `messages/` の10個のJSONファイル。
- インターフェイス: `AuthI18n.tsx`、`AuthPublic.tsx`、`Login.tsx`、`Brand.tsx`、`ThemeToggle.tsx`、および `Turnstile.tsx` が `src/components/` にあります。
- ロードとパブリックルート: `src/layouts/Base.astro`、`src/pages/index.astro`、`login.astro`、`login/complete.astro`、`denied.astro`、および `404.astro`。
- スタイルとフォント: `src/styles/global.css`、`public/fonts/`、`scripts/build-auth-fonts.py`、および `docs/licenses/noto-fonts.txt`。
- リクエストとメールの提示: `src/lib/utils.ts`、`src/server/auth.ts`、`src/server/index.ts`、および `src/server/services/auth-mail.ts`。
- テスト: `tests/auth-i18n.test.ts`、`tests/auth.test.ts`、および `tests/browser/auth-i18n.mjs`。ドキュメント: このファイル、`docs/validation.md`、`README.md`、および `CHANGELOG.md`。

## 検証

`tests/auth-i18n.test.ts` は10個のカタログ、パラメータ、バリアント、優先度、ヘッダーの解決、フォールバック、方向、エラー、正規化、メールテキストを検証します。`tests/auth.test.ts` での統合は、Better AuthとD1ロケールを使用して10個の言語でOTPを提供し、使用の唯一性を確認します。実際のメールは送信されません。

`tests/browser/auth-i18n.mjs` は、すでに利用可能なPlaywrightとシミュレートされたAPIを使用します。ローカルに提供されたビルドに対して実行されます。

```sh
AUTH_TEST_URL=http://127.0.0.1:4321 \
PLAYWRIGHT_MODULE=/ruta/a/playwright/index.js \
node tests/browser/auth-i18n.mjs
```

これには、ハイドレーションの前検出、点滅の不存在、永続性、ナビゲーションまたはリクエストのない即時変更、フォームとロードの保存、10個の言語の入力/登録/OTP/MFA/回復、エラー、ヘルプ、パブリックページ、ブロックされたストレージ、CAPTCHA、再認証の通知、320、390、768、1440pxの幅が含まれます。追加の視覚的なチェックでは、アラビア語、ヒンディー語、中国語、日本語、ドイツ語、フランス語の実際のフォントとデスクトップ/モバイルが確認されます。

英語はフォールバックとして初期バンドルに含まれます。他のログイン・管理画面カタログは動的インポートとモジュール別メモリーキャッシュを使います。キーボードやポインターのフォーカスで該当オプションのみ先読みし、メニューを開くだけでは全言語を読み込みません。カタログが揃ってから切り替え、フォーム・セッション・画面遷移状態を保持します。キャッシュ済みの変更は通信不要で最後の選択が優先されます。初回失敗は英語、切り替え失敗は現在の言語を表示します。メールとビルド用メタデータは完全なサーバー専用辞書を使います。[言語読み込み](language-loading.md)を参照してください。
