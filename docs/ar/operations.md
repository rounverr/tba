يستخدم TBA افتراضيًا Cloudflare Workers مع D1. تعمل الواجهة نفسها وواجهة Hono API أيضًا على Node.js مع SQLite أو PostgreSQL. [محركات قواعد البيانات](database-engines.md)

## بدء التشغيل

الإنجليزية لغة أساس الشيفرة ومساعد setup. تأتي الترجمات العشر والخطوط المحلية ضمن الحزمة. يفعّل `npm run setup -- --languages en,pt` الإنجليزية والبرتغالية فقط دون تثبيت حزم إضافية أو حذف الترجمات الأخرى. يحفظ حذف الخيار `--languages` الاختيار الحالي، أو يفعّل العشر إن لم توجد قائمة. تبقى الإنجليزية مفعلة كمرجع احتياطي للترجمات. يحدد `--locale en` لغة التطبيق الافتراضية ويقبل أي لغة مفعلة. الأولوية للتفضيل المحفوظ ثم لغة المتصفح المدعومة ثم الافتراضية المحددة. لا يعيد تغيير اللغة تحميل الصفحة أو ضبط النماذج؛ وتبقى العربية RTL.

`npm run setup -- --interactive` | `--name` | `--id` | `--domain` | `--database` | `--account` | `--mail local|resend|cloudflare` | `--google true|false` | `--mfa true|false` | `--trust true|false` | `--r2 true|false` | `--theme light|dark`.

ينشئ البرنامج النصي `.dev.vars` مع سر فريد عند عدم وجوده. لا يكتب بيانات اعتماد في الملفات المنسقة ولا ينشئ مسؤولين أو موارد بعيدة. يعدل الهوية الفنية قبل توفير مشتق.

## D1 و Drizzle و الهجرات

`src/server/database/schema.ts` هو مخطط Drizzle. `drizzle/0001_initial.sql` يحتوي على مخطط القاعدة و `0002_defaults_and_guards.sql` يتحمل الأدوار والتسجيل المغلق والزناد. `drizzle/generated` يحافظ على لقطة Drizzle للمقارنات المستقبلية؛ Wrangler ينفذ فقط SQL في الجذر من `drizzle`. طبّق `drizzle/0003_session_authorization.sql` مع بقية الترحيلات. تحصل الجلسات الحالية على لقطة عند التحقق التالي من الأذونات.

`db:generate` ينتج مرشحين في `drizzle/generated`. راجع كل مرشح وانسخه بالرقم التالي في الجذر؛ أضف الزناد أو البيانات في هجرة منفصلة عند الاقتضاء. لا تедакل هجرة تم تطبيقها بالفعل. راجع الصراعات المحتملة قبل استخدام D1 موجودة وقم بنسخ احتياطي قبل التغييرات البعيدة. لا تنفذ القالب SQL عن بعد أثناء التثبيت أو البناء.

> [!IMPORTANT]
> البرامج النصية `db:create` و `db:link` و `db:migrate:remote` و `deploy` تتطلب حسابًا صريحًا و `--confirm`؛ بدون تأكيد تتوقف عمليات الإنشاء والكتابة. `db:create` يتحقق من الأسماء الحالية ويعيد UUID الفعلي. `db:link` يعدد قواعد البيانات للحساب ويعرض مخططها قبل حفظ الربط، دون تعديله. إذا فشلت عملية، لا يُكتب ربط مفترض. لا يزيل أي برنامج نصي قواعد بيانات.

استخدم `--config wrangler.<environment>.jsonc` أو `--config wrangler.<other-environment>.jsonc` لأهداف منفصلة. انسخ الإعدادات وassign اسمًا و URL و account_id و database_id حقيقيين مختلفين لكل بيئة. لا ينبغي مشاركة المتغيرات والارتباطات عن طريق الخطأ. لا توجد بيئات بعيدة مسبقة في TBA.

## أسرار وبريد

يدعم الإعداد `--mail local` و`--mail resend` و`--mail cloudflare`. يستخدم البريد المحلي `APP_URL` محليًا و`npm run mail:dev`، ويحتاج Resend إلى `RESEND_API_KEY` و`MAIL_FROM`. يعيد Cloudflare استخدام المحول الحالي ويتطلب ربط `send_email` باسم `EMAIL` و`MAIL_FROM` مسموحًا ونطاق إرسال مجهزًا. يتحقق الإعداد محليًا دون إنشاء موارد أو التحقق من نطاق بعيد. يمكن تأجيل الإعداد: يسأل الوضع التفاعلي عن المتابعة، ويتابع غير التفاعلي بقائمة مهام معلقة. لا يخترع ربطًا أو مرسلًا أو بيانات اعتماد؛ لا يعمل الإرسال حتى اكتمال الإعداد. احفظ الأسرار خارج Git. يبقى Wavicc التكامل المستقبلي المفضل و`WAVICC_API_KEY` حقلًا محجوزًا. راجع [إعداد البريد](setup-mail.md).

Wavicc التكامل المستقبلي المفضل، دون محول أو عقد API متحقق منه. لا تفعّل placeholders مثل `WAVICC_API_KEY` و`CUSTOM_MAIL_API_KEY` خدمة. لا تستخدم `MAIL_PROVIDER=wavicc`. تتطلب الخدمة الأخرى محولًا مختبرًا وفق عقدها المنشور مع حفظ HTML والنص والمصادقة؛ لا تُفترض هنا نقاط نهاية.

اختبر كل رسالة بحسابات معزولة: اللغة والمحمول والانتهاء وفشل الإرسال ونتيجة التغييرات المؤكدة. لا تسجل الرموز أو المحتوى أو الرموز المميزة أو الأسرار. راجع [العمليات](operations.md) و[التحقق](validation.md).

## جوجل و تيرنستيل

جوجل يتطلب `GOOGLE_ENABLED="true"` و `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` مع استدعاء دقيق `/api/auth/callback/google`. لا توجد قيم افتراضية. استخدم حسابًا نشطًا تم تفعيله مسبقًا وافحص التحقق من عامل التحقق الثنائي ورفض المستخدمين الموقوفين والبريد الإلكتروني المُؤكد قبل النشر.

تيرنستيل اختياري. إذا حددت `TURNSTILE_SITE_KEY`، حدد أيضًا `TURNSTILE_SECRET_KEY`. يسجل السجل الشبكي ويتحقق الخادم الخلفي من رمز العامل والمضيف وعملية `register` في Siteverify؛ لا يكفي حل الشبكة في رياكت. لا يتم إنشاء شبكات بعيدة من TBA. إذا لم يتم تكوينها، يستمر الحد D1 النشط للبريد الإلكتروني والعنوان IP والتحقق. تقييم تمكينها قبل فتح التسجيل للجمهور.

R2 معطل ولا يتم إعلان الحاويات. أضفه فقط إذا كان المشتق يحتاج إلى ملفات، مع تفويض صريح للتزويد وأنواع إعادة التوليد.

## مسؤول أول

`npm run admin:bootstrap -- --email admin@example.test` يستخدم D1 المحلي افتراضيًا. لا يتم وضع علامة على البريد الإلكتروني على أنه مُؤكد ويجب تأكيده باستخدام OTP. لا يتم إضافة مسؤول آخر إذا كان هناك مسؤول نشط بالفعل.

الوضع البعيد يتطلب `--remote --account ACCOUNT_ID --confirm` ويتحقق من أن التكوين يحتوي على D1 حقيقي و同じ الحساب. لا تشمل البريد الإلكتروني الحقيقي في SQL المنسق. إذا فقدت الوصول إلى المسؤول الوحيد، اتبع إجراءً تشغيليًا خاصًا؛ لا يوجد باب خلفي ولا إعادة تعيين تلقائي للصلاحيات.

## النشر اليدوي باستخدام D1

1. قم بتكوين هوية المشتق والحساب الصحيح.
2. أنشئ أو ربط D1 بعد الموافقة. راجع وتطبيق SQL صراحة.
3. قم بتكوين HTTPS والمصدر الدقيق والبريد الإلكتروني الخارجي؛ اختياريًا جوجل وتيرنستيل.
4. قم بتشغيل `types:worker` و `check` و `test` و `build` و `worker:check`.
5. قم بتشغيل `npm run deploy -- --account ACCOUNT_ID --confirm` مع الملف المحدد.
6. قم بتشغيل التمهيد البعيد واختبار مع مستخدمين معزولين.
7. قم بالتحقق من الأحداث و MFA والاستعادة والأدوار وflux البريد الإلكتروني قبل قبول المستخدمين الحقيقيين.

التكوين يتضمن سجلات وتتبع العمال. تجنب إضافة سجلات للجسم / الكعكات. تُجرى عمليات التحقق والنشر يدويًا. GitHub Actions و Workers Builds ليست متطلبات لنشر ولا ينبغي تكوينها كشرط للنشر. قم بتشغيل الفحوصات المحلية ذات الصلة قبل أي تغيير عن بُعد، مع الحساب والوجهة المؤكدة.

## تحديثات ومشاكل شائعة

- خطأ في المصدر: `APP_URL` يجب أن يتطابق مع مصدر المتصفح، بدون شريط نهائي. استخدم العامل المحلي للاختبار الكامل.
- لا يصل OTP: راجع البريد المحلي أو المرسل / بيانات اعتماد المزود. الاستجابة العامة لا تؤكد وجود الحساب.
- الوصول المرفوض: أكد الحالة النشطة والبريد الإلكتروني المُؤكد والدور والتحقق من عامل التحقق الثنائي الكامل في الخادم الخلفي.
- تغيير حساس مرفوض: أعد تسجيل الدخول؛ التحقق الأخير يستمر لمدة خمس دقائق.
- D1 غير موجود: قم بتطبيق الهجرات المحلية أو التحقق من الربط البعيد والحساب؛ لا تملأ IDs المخترعة.
- تحديث النواة: قارن بين التعديلات، راجع `CHANGELOG`، قم بتحديث التبعيات بشكل متعمد، وقم بتطبيق الهجرات المُراجعة في مرحلة ما قبل الإنتاج. GitHub Template لا ينتشر التغييرات إلى المشتقات.
