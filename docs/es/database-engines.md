> [!NOTE]
> TBA admite D1 en Cloudflare Workers y SQLite o PostgreSQL en Node.js 24+. Utilice una copia del código por instalación. `npm run setup -- --interactive` muestra el selector y guarda la elección en `tba.runtime.json`. El argumento `--db-engine` acepta `d1`, `sqlite` o `postgresql`. D1 es el predeterminado y `--database` indica el nombre de la base D1. Para Node están disponibles `--host`, `--port` y `--domain`. SQLite también admite `--sqlite-path`. Guarde `DATABASE_URL` y `BETTER_AUTH_SECRET` en `.dev.vars` o en el entorno y conserve el mismo secreto entre reinicios.

D1 y SQLite aplican los archivos SQL 0001 a 0003 de `drizzle/`. PostgreSQL aplica sus propios archivos numerados de `drizzle/postgresql/`. Cada instalación conserva su historial.

Ejecute `npm ci`, el instalador y `npm run build`. En D1 o SQLite, aplique las migraciones con `npm run db:migrate:local` e inicialice con `npm run admin:bootstrap -- --email admin@example.test`. En PostgreSQL, agregue `--target tba_db` después de `--` en ambos comandos. Para conexiones fuera de loopback, indique `host:puerto/base` y use TLS. `PG_CA_FILE` permite configurar una CA privada. Inicie con `npm start`. `npm run dev` compila e inicia Node en los motores independientes. En D1 conserva Astro y `npm run dev:worker` inicia el Worker. `npm run worker:check` está reservado para D1.

`better-sqlite3` es opcional al instalar y se requiere únicamente para SQLite. Si falta el driver, use `npm ci --include=optional` con una plataforma y versión de Node compatibles. Si no hay un binario compatible, consulte el procedimiento de compilación nativa del driver. Use también `npm ci` para D1 y PostgreSQL. Omitir todas las dependencias opcionales puede quitar paquetes de plataforma necesarios para el build. Conserve SQLite en almacenamiento persistente fuera de `dist`, con respaldos consistentes. Para PostgreSQL, use `pg_dump` y pruebe la restauración.

Las migraciones del núcleo requieren la sintaxis `CREATE TRIGGER ... EXECUTE FUNCTION` de PostgreSQL 11 y usan columnas identity y JSONB. PostgreSQL 11 es el mínimo teórico para el SQL. La matriz de pruebas del núcleo usa 17.12 y 18.7. Consulte el calendario de mantenimiento oficial. Para instalaciones nuevas se recomienda el último parche de PostgreSQL 18 o, si es necesario, de PostgreSQL 17 mientras reciba mantenimiento. [Sintaxis de triggers](https://www.postgresql.org/docs/11/sql-createtrigger.html) | [Política de versiones de PostgreSQL](https://www.postgresql.org/support/versioning/)

El buzón local se ejecuta con `npm run mail:dev` y usa `http://127.0.0.1:8025`. Para publicar Node, use HTTPS, un proxy que preserve el Host público y Resend con un remitente verificado. De forma predeterminada, el límite por IP usa la dirección del socket. Si se define `TRUSTED_PROXIES` con las IP o los rangos CIDR IPv4/IPv6 de proxies bajo su control, Node acepta un solo encabezado `X-Forwarded-For` válido del par autorizado y selecciona el primer salto no confiable desde la derecha. El proxy de entrada debe sobrescribir o sanear ese encabezado. Restrinja el acceso directo al backend cuando corresponda. [Operaciones D1](operations.md) | [Configuración de correo](setup-mail.md)

Quedan pendientes la instalación y los junctions en Windows, el callback externo de Google OAuth, la entrega real mediante Resend y un pentest independiente que cubra explotación y temporización SQL. Las certificaciones de seguridad y cumplimiento quedan fuera del alcance de estas validaciones.
